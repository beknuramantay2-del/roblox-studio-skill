# Roblox API и работа с документацией

## Проверяй документацию перед использованием API

Roblox меняется каждую неделю: методы устаревают, появляются новые сервисы, у существующих классов добавляются свойства. Твои знания об API имеют дату, и она в прошлом. Поэтому перед использованием незнакомого или редкого API сверься с актуальной документацией на create.roblox.com/docs, а не полагайся на память.

Особенно это важно, когда:

- API касается монетизации, DataStore, MemoryStore, TeleportService: здесь чаще всего меняются лимиты и подписи функций.
- Ты собираешься использовать что-то, что помнишь смутно. Смутное воспоминание об API даёт код, который выглядит правильным и не работает.
- Код падает с ошибкой вида "is not a valid member" или "attempt to call a nil value": скорее всего метод переименован или удалён.

Не выдумывай методы. Если не уверен, что `Humanoid:SomeMethod()` существует, проверь. Придуманный API — худший вид ошибки, потому что выглядит уверенно и ломается только в рантайме.

## Как искать нужный класс или метод

Ищи по задаче, а не по названию. Обычно путь такой:

1. **Определи, что это за сущность.** Объект в мире — класс-наследник `Instance`. Глобальная возможность — сервис через `game:GetService`. Значение — datatype (`Vector3`, `CFrame`, `Color3`, `UDim2`, `Enum`).
2. **Посмотри наследование.** `Part` наследует `BasePart`, тот `PVInstance`, тот `Instance`. Половина нужных свойств лежит в родительских классах: `Anchored` и `CanCollide` принадлежат `BasePart`, а не `Part`, и искать их надо там.
3. **Проверь Enum.** Многие свойства принимают только значения перечислений: `Material`, `EasingStyle`, `HumanoidStateType`, `KeyCode`. Строку вместо Enum движок не примет.
4. **Пользуйся автодополнением Studio**, если не помнишь точное имя значения: `Enum.KeyCode.` показывает список.

В живой сессии проверить структуру можно прямо кодом: `print(object:GetFullName(), object.ClassName)`, `object:IsA("BasePart")`, обход через `GetChildren`. Это надёжнее догадок о чужом проекте.

## Устаревшее API

Deprecated-методы обычно ещё работают, но: медленнее, глушат ошибки, могут отключиться в любой момент. Заменяй при встрече в новом коде.

| Устарело | Замена |
| --- | --- |
| `wait()`, `spawn()`, `delay()` | `task.wait()`, `task.spawn()`, `task.delay()` |
| `:connect()`, `:remove()` | `:Connect()`, `:Destroy()` |
| `BodyPosition`, `BodyGyro`, `BodyVelocity` | `AlignPosition`, `AlignOrientation`, `LinearVelocity` |
| `Weld` с ручными C0/C1 | `WeldConstraint` |
| `Humanoid:LoadAnimation()` | `Animator:LoadAnimation()` |
| `Instance.new("Class", parent)` | свойства сначала, `Parent` последним |
| `game.Workspace`, `game.Players` | `workspace`, `game:GetService("Players")` |
| `FindPartOnRay`, `Ray` | `workspace:Raycast` с `RaycastParams` |
| `Humanoid.Died` для урона от кастомных систем | считай урон сам, `Died` только как факт смерти |

Если встретил deprecated API в существующем коде пользователя — скажи об этом, но не переписывай без спроса. Незапрошенный рефакторинг чужого кода путает больше, чем помогает.

## Script Analysis

В Studio есть встроенный анализатор. Он ловит опечатки в именах свойств, недостижимый код, неиспользуемые переменные, конфликты типов. С `--!strict` его польза вырастает в разы.

Правило: **пустая панель Script Analysis — часть определения "готово"**. Предупреждение анализатора почти всегда указывает на реальный баг, который иначе всплывёт через час игры. Не игнорируй их и тем более не убирай strict, чтобы "избавиться от красного".

## Сервисы

Всегда через `game:GetService("Name")`, а не `game.Name`. `GetService` работает, даже если сервис ещё не создан или переименован, и это единственный корректный способ.

Кэшируй ссылки в начале файла:

```lua
local Players = game:GetService("Players")
local RunService = game:GetService("RunService")
local TweenService = game:GetService("TweenService")
```

Сервисы — синглтоны, `GetService` дважды вернёт один и тот же объект.

## Определение стороны в коде

```lua
if RunService:IsServer() then ... end
if RunService:IsClient() then ... end
if RunService:IsStudio() then ... end -- отладочные ветки только для Studio
```

Полезно в модулях, которые требуются с обеих сторон: можно защититься от вызова серверной функции на клиенте явной ошибкой вместо загадочного поведения.
