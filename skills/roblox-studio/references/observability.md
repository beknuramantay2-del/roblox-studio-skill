# Наблюдаемость и диагностика

Если агент не видит состояние, он начинает гадать. Каждая система должна оставлять короткие, полезные сигналы.

## Логи

Используй префикс и event name:

```lua
print("[Shop] purchase_success", player.UserId, itemId)
warn("[Data] load_failed", player.UserId, err)
```

Не логируй секреты, полный пользовательский текст, токены или лишние персональные данные. Не спамь логом каждый кадр.

## Сигналы

Для критичных систем измеряй latency remote, количество отказов, DataStore errors, активные NPC, созданные эффекты, число игроков, память и FPS. Сравнивай до/после изменения.

## Correlation id

Для длинной операции передавай короткий request id через серверный контекст и логируй его на старте, результате и ошибке. Не принимай client request id как доказательство личности.

## Ошибка как состояние

Ошибку показывай трём аудиториям: игроку понятный fallback, Output точная причина, разработчику путь и шаг воспроизведения. Пустой catch/pcall запрещён.
