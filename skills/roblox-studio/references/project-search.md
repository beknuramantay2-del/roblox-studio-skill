# Поиск и карта проекта

Большой Roblox-проект нельзя изучать линейно. Сначала собери карту, затем ищи только связанные ветки. Roblox выделяет отдельный Data Model Search именно по этой причине: длинное исследование засоряет контекст главного агента и ухудшает решения.

## Карта проекта

Перед изменением составь короткую карту:

- ключевые контейнеры: `Workspace`, `ServerScriptService`, `ReplicatedStorage`, `StarterPlayer`, `StarterGui`, `StarterPack`;
- точки входа сервера и клиента;
- сервисы и контроллеры;
- `Remotes`;
- хранилища данных;
- важные теги и атрибуты;
- текущий режим Studio: Edit, Run или Play;
- активные ошибки Output.

Формат карты: 10-20 строк, только то, что меняет решение. Не копируй весь Explorer в контекст.

## Поиск

Используй несколько узких запросов вместо одного огромного обхода:

1. объекты по точному имени;
2. объекты по классу через `IsA`;
3. скрипты по содержимому и ключевым словам;
4. references на имя функции, переменной, remote или атрибута;
5. `require` и зависимости ModuleScripts;
6. теги `CollectionService` и вызовы `GetAttribute`.

Перед созданием объекта проверь имя, класс и родителя. Одинаковые имена допустимы, поэтому совпадение имени без проверки полного пути недостаточно.

## Зависимости

Для каждой изменяемой системы составь цепочку:

`вход → controller/local script → remote → server service → data/config → UI или мир`.

Не меняй функцию, пока не нашёл все её вызовы и подписчиков. Не удаляй ModuleScript, пока не проверил `require`, косвенные ссылки по имени и remote-контракты.

## Контроль объёма

Если найдено больше 5 потенциально связанных файлов, не читай их все подряд: сначала выбери точку входа и ближайший контракт. Остальное догружай только при обнаружении зависимости. Это сохраняет контекст и уменьшает случайные правки.

В отчёте после разведки укажи: найдено, связано напрямую, рискованно менять, что проверишь после изменения.
