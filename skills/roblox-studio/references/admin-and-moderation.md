# Админ-системы и модерация

Аудитория детская, значит модерация не опция. Плохо защищённая админка означает читера с правами администратора, а отсутствие фильтрации — жалобы родителей и риск для игры.

## Админ-панель

Единственный безопасный способ проверить права — **на сервере, по `UserId`, из списка в серверном коде**.

```lua
-- В ServerScriptService: клиент этот список не видит и не изменит.
local ADMINS = table.freeze({
	[123456789] = "Owner",
	[987654321] = "Moderator",
})

local function getRank(player: Player): string?
	return ADMINS[player.UserId]
end
```

Чего делать нельзя ни при каких обстоятельствах:

- Проверять права **по имени игрока**: имена меняются, и аккаунт с похожим именем получит доступ.
- Хранить список админов в `ReplicatedStorage`: клиент прочитает его и узнает, кого атаковать.
- Проверять права на клиенте: клиентская проверка означает админку для всех.
- Принимать от клиента признак "я админ" в любом виде.

Каждая админ-команда проверяет права **заново на сервере**, а не полагается на то, что UI показан только админу. Клиент может вызвать remote напрямую, минуя UI.

```lua
Remotes.AdminCommand.OnServerEvent:Connect(function(player, command, argument)
	local rank = getRank(player)
	if not rank then
		warn("[Admin] попытка без прав:", player.Name, player.UserId, command)
		return  -- и логируй: это признак читера
	end
	if not RemoteGuard.isString(command, 32) then return end

	local handler = Commands[command]
	if not handler then return end
	if not hasPermission(rank, command) then return end

	local ok, err = pcall(handler, player, argument)
	if not ok then
		warn("[Admin] команда упала:", command, err)
	end
end)
```

Логируй каждое использование админ-команды с именем, id и параметрами. Когда что-то пойдёт не так, это единственный способ понять, кто и что сделал.

Разделяй уровни прав: модератор может кикнуть и заглушить, владелец может менять экономику. Один уровень "админ" на всё означает, что доверенный друг может случайно сломать игру.

Опасные команды (выдать валюту, сбросить данные) держи только у владельца и добавь подтверждение. Соблазн выдать себе миллион монет для теста ломает экономику в проде, если команда осталась включённой: держи её за проверкой `RunService:IsStudio()`.

## Фильтрация текста

Любой текст от игрока, который увидит другой игрок, обязан пройти через `TextService`. Это требование Roblox, а не рекомендация: невыполнение ведёт к санкциям на игру.

```lua
local TextService = game:GetService("TextService")

local function filterFor(text: string, fromUserId: number, toPlayer: Player): string
	local ok, result = pcall(function()
		local filtered = TextService:FilterStringAsync(text, fromUserId)
		return filtered:GetChatForUserAsync(toPlayer.UserId)
	end)
	-- При сбое фильтрации показываем заглушку, а НЕ исходный текст.
	if not ok then
		warn("[Filter] не удалось отфильтровать")
		return "..."
	end
	return result
end
```

Где это нужно: имена питомцев и баз, таблички, кастомные сообщения, названия команд, любой ввод в `TextBox`. Фильтровать надо **для каждого получателя отдельно**: Roblox фильтрует с учётом возраста и настроек конкретного игрока.

При сбое фильтрации показывай заглушку, а не оригинал. Пропустить нефильтрованный текст хуже, чем показать точки.

Дополнительно к фильтру: ограничивай длину ввода, запрещай повторяющиеся символы и проверяй, что имя не пустое после фильтрации.

## Кик, бан, мут

```lua
-- Кик: сообщение обязательно понятное. Дети не понимают кодов ошибок.
player:Kick("Ты был отключён за нарушение правил. Возвращайся позже!")
```

Бан храни в отдельном DataStore по `UserId` со сроком и причиной, проверяй в `PlayerAdded`. Проверка через `pcall`: если DataStore недоступен, **пускай игрока**, а не блокируй всех. Иначе сбой сервиса закроет игру для всей аудитории.

```lua
local function onPlayerAdded(player: Player)
	local ok, ban = pcall(function()
		return banStore:GetAsync(tostring(player.UserId))
	end)
	if not ok then return end  -- сбой: пускаем
	if not ban then return end
	if ban.Until and ban.Until < os.time() then return end  -- срок истёк

	player:Kick(`Доступ ограничён: {ban.Reason}`)
end
```

Мут делай отключением возможности отправлять сообщения на сервере, а не скрытием поля ввода на клиенте: второе обходится.

Временный бан почти всегда лучше постоянного, особенно с детской аудиторией: ребёнок, нарушивший правила случайно, не должен терять доступ навсегда.

## Античит: что реально работает

Подробно в `security.md`. Здесь главное: античит — это **серверная проверка правдоподобности**, а не клиентский детектор.

Что проверять на сервере: скорость перемещения, частоту действий, дистанцию до объекта взаимодействия, скорость прогресса, физически невозможные позиции (под картой, вне границ).

Чего не делать: `LocalScript`-детекторы (отключаются), обфускация (читается), доверие клиентским отчётам о читерстве (подделываются), автобан по одному срабатыванию.

**Не кикай сразу.** Лаги, телепорты движка и просадки дают ложные срабатывания. Копи подозрения и реагируй при устойчивом паттерне. Несправедливо выкинутый ребёнок не вернётся и оставит плохой отзыв, а это дороже одного пропущенного читера.

Логируй аномалии всегда, даже когда не реагируешь: по логам видно реальные способы обхода, а не воображаемые.

## Отчёты игроков

Встроенная кнопка Report у Roblox есть по умолчанию, свою систему делать не обязательно. Если делаешь: фильтруй текст жалобы, ограничивай частоту, и не показывай другим игрокам, кто на кого пожаловался. Публичные жалобы в детской игре превращаются в травлю.
