# Валюта, инвентарь, магазин, квесты, прогрессия

Всё в этом файле серверное. Любая валюта или предмет, начисляемый по слову клиента, означает сломанную экономику через день после релиза.

## Валюта и leaderstats

`leaderstats` — специальная папка внутри игрока, содержимое которой Roblox показывает в списке игроков. Это витрина, а не хранилище.

```lua
local function setupLeaderstats(player: Player)
	local stats = Instance.new("Folder")
	stats.Name = "leaderstats"  -- имя строго такое, иначе не сработает

	local coins = Instance.new("IntValue")
	coins.Name = "Монеты"       -- это имя видят игроки
	coins.Value = 0
	coins.Parent = stats

	stats.Parent = player
end
```

Важно: **истина в данных игрока, а не в `IntValue`**. Обновляй `leaderstats` из сервиса данных, а не наоборот. Иначе табло и реальный баланс разойдутся, и игрок будет видеть одно, а покупать за другое.

Валюту меняй только через одну функцию сервиса, которая проверяет знак, лимит и NaN и там же обновляет UI с leaderstats. Разбросанные по коду `data.Coins += x` рано или поздно дадут отрицательный баланс.

```lua
function CurrencyService.add(player: Player, amount: number, reason: string): boolean
	if not RemoteGuard.isNumber(amount, -MAX_TRANSACTION, MAX_TRANSACTION) then
		warn("[Currency] некорректная сумма:", amount, reason)
		return false
	end
	local data = DataService.Get(player)
	if not data then return false end

	local newValue = math.max(0, data.Coins + amount)  -- ниже нуля не уходим
	data.Coins = newValue
	updateLeaderstats(player, newValue)
	Remotes.BalanceUpdated:FireClient(player, newValue)
	return true
end
```

Параметр `reason` не для красоты: в логах видно, откуда пришли монеты, и это единственный практичный способ найти дырку в экономике.

## Предметы и инвентарь

Определения предметов в `Shared/Config`, чтобы клиент знал названия, иконки и цены без запросов. Владение — в данных игрока на сервере.

```lua
Items = table.freeze({
	SpeedBoost = table.freeze({
		Name = "Ускорение",
		Icon = "⚡",
		Price = 100,
		Rarity = "Common",
		MaxStack = 99,
	}),
})
```

В сохранении держи только количество по id: `{ SpeedBoost = 3 }`. Не дублируй названия и цены в данных игрока: при изменении баланса старые сохранения начнут противоречить конфигу.

При выдаче проверяй: существует ли id в конфиге, не превышен ли `MaxStack`, есть ли место. Проверка существования в белом списке (`Config.Items[id]`) обязательна: без неё клиент попросит предмет `SuperGodSword` и получит его.

UI инвентаря: сетка через `UIGridLayout`, крупные иконки, цвет рамки по редкости, количество в углу. Подробнее в `ui-screens.md`.

## Магазин

Поток покупки, где каждый шаг обязателен:

1. Клиент нажимает, шлёт `RequestPurchase(itemId)`.
2. Сервер: кулдаун, тип аргумента, существование в белом списке.
3. Сервер: хватает ли валюты **прямо сейчас**, а не по данным из UI клиента.
4. Сервер: списывает валюту и выдаёт предмет.
5. Сервер: отвечает результатом, обновляет баланс и инвентарь у клиента.

Списание и выдача неразделимы. Если между ними что-то упадёт, игрок останется без монет и без предмета, и это худший вид бага в детской игре: ребёнок уверен, что его обманули.

```lua
-- Сначала проверяем всё, потом меняем состояние. Никаких частичных изменений.
local item = Config.Items[itemId]
if not item then return end
if data.Coins < item.Price then
	Remotes.PurchaseFailed:FireClient(player, "not_enough")
	return
end
if getStack(data, itemId) >= item.MaxStack then
	Remotes.PurchaseFailed:FireClient(player, "full")
	return
end

data.Coins -= item.Price
giveItem(data, itemId, 1)
DataService.Save(player)  -- покупки сохраняем сразу, не ждём автосейв
```

Сохраняй сразу после покупки. Если сервер упадёт до автосейва, ребёнок потеряет купленное, и это самая частая причина гневных сообщений в детских играх.

При отказе всегда объясняй причину картинкой и текстом: "Не хватает 50 монеток" с иконкой. Молчаливый отказ читается как поломка.

## XP и уровни

Формула должна быть чистой функцией: уровень считается из XP, а не хранится рядом с ним. Два источника истины неизбежно разойдутся.

```lua
local BASE_XP = 100
local GROWTH = 1.15

function Levels.fromXp(xp: number): number
	local level, required = 1, BASE_XP
	while xp >= required do
		xp -= required
		level += 1
		required = math.floor(required * GROWTH)
	end
	return level
end
```

Коэффициент роста 1.1-1.2 даёт комфортную кривую. Больше 1.3 и после десятого уровня прогресс встанет, дети уйдут.

Повышение уровня обязательно празднуй: анимация, звук, вспышка, награда. Уровень без праздника не мотивирует. Прогресс-бар должен быть виден постоянно и заполняться заметно после каждого действия: ощущение движения важнее скорости движения.

## Квесты

Определения в конфиге, прогресс в данных игрока.

```lua
Quests = table.freeze({
	Collect10Coins = table.freeze({
		Title = "Собери 10 монеток",
		Icon = "🪙",
		Goal = 10,
		Reward = table.freeze({ Coins = 50, Xp = 20 }),
	}),
})
```

Продвижение квеста делай через события внутри сервера, а не прямыми вызовами из механик:

```lua
-- механика сообщает факт, квесты сами решают, важен ли он
QuestService.report(player, "CoinCollected", 1)
```

Это ключевое архитектурное решение. Без него каждая новая цель квеста означает правку в механике, и через десять квестов код сбора монет превратится в свалку условий.

Правила для детской аудитории: одна активная цель на виду, максимум 2-3 в списке. Прогресс виден числом и полоской. Награда выдаётся сразу и заметно. Квест не должен требовать больше 10-15 минут.

## Daily rewards

```lua
local function getDayNumber(): number
	return math.floor(os.time() / 86400)  -- UTC-день, одинаковый для всех
end

function DailyService.claim(player: Player): (boolean, string?)
	local data = DataService.Get(player)
	if not data then return false, "not_ready" end

	local today = getDayNumber()
	if data.LastClaimDay == today then
		return false, "already_claimed"
	end

	-- Стрик продолжается только если заходил вчера
	data.Streak = if data.LastClaimDay == today - 1 then data.Streak + 1 else 1
	data.LastClaimDay = today
	CurrencyService.add(player, rewardForStreak(data.Streak), "daily")
	DataService.Save(player)
	return true, nil
end
```

Считай дни через `os.time()` на сервере, никогда через локальное время клиента: часовой пояс подкручивается тривиально.

Награда растёт по дням, а сброс стрика делай щедрым (прощай один пропущенный день). Жёсткий сброс наказывает ребёнка за то, что его не пустили к компьютеру, и он не вернётся.

## Achievements

Проверяй достижения там же, где обрабатываешь события квестов, одним потоком, а не отдельными подписками по всему коду. Выдача через `BadgeService` (см. `monetization.md`) делает достижение видимым в профиле Roblox, что для детей ценно само по себе.

Достижения должны быть видимы **до** получения: список с закрытыми ячейками мотивирует, невидимые сюрпризы нет.

## Балансировка для детской аудитории

- **Первая награда в первые 30 секунд.** Ребёнок решает, играть ли, почти сразу.
- **Никогда не отбирай прогресс.** Ни за смерть, ни за выход, ни за проигрыш. Потеря вызывает обиду, а не желание отыграться.
- **Цены кратные и понятные:** 50, 100, 250, 500. Цена 137 монет требует счёта, которого от игрока ждать не надо.
- **Первая покупка доступна за 2-3 минуты игры.** Если первый предмет стоит час фарма, магазин для ребёнка не существует.
- **Кривая роста мягкая.** Каждое следующее улучшение дороже примерно в 1.5-2 раза, не в десять.
- **Все цифры в `Shared/Config`,** чтобы правка баланса была правкой одной строки, а не поиском по проекту.
