# Процедурная генерация

## Сначала реши, зачем

Процедурная генерация оправдана, когда нужна переиграемость или бесконечный контент. Она **не** способ сэкономить на дизайне: сгенерированная карта почти всегда скучнее собранной руками, если генератор не продуман.

Честный компромисс, который работает в детских играх: генерируй **компоновку** из готовых, сделанных руками кусков. Комнаты, платформы, секции обби собраны вручную и красивы, а генератор только решает, в каком порядке их поставить. Это даёт разнообразие без ощущения безликости.

## Seed: без него генерация неотлаживаема

```lua
local seed = os.time()          -- или фиксированный для теста
local rng = Random.new(seed)
print("[Gen] seed =", seed)     -- ОБЯЗАТЕЛЬНО логируй
```

Логируй seed всегда. Когда пользователь скажет "карта сгенерировалась сломанной", единственный способ воспроизвести это — тот же seed. Без него ты будешь чинить наугад.

Используй `Random.new(seed)`, а не `math.random`: только объект `Random` даёт воспроизводимую последовательность.

## Генерация из готовых кусков

```lua
local function generateCorridor(sections: { Model }, count: number, rng: Random)
	local container = Instance.new("Folder")
	container.Name = "GeneratedMap"

	-- Точка стыковки: у каждой секции Attachment с именем "Exit"
	local cursor = CFrame.new(0, 0, 0)

	for index = 1, count do
		local template = sections[rng:NextInteger(1, #sections)]
		local section = template:Clone()
		section:PivotTo(cursor)
		section.Parent = container

		local exit = section:FindFirstChild("Exit", true)
		if not exit then
			warn("[Gen] у секции нет Exit:", template.Name)
			break  -- лучше короткая карта, чем куча-мала
		end
		cursor = exit.WorldCFrame
	end

	container.Parent = workspace
	return container
end
```

Ключевые детали:

- **Стыковка через `Attachment`,** а не через размеры части. Размеры меняются при редизайне секции, а точка входа-выхода остаётся осмысленной.
- **`PivotTo` на модели,** не `Position` на частях: иначе секция разъедется.
- **Проверяй наличие точки стыковки** и падай осмысленно. Молчаливый пропуск даёт карту, где секции наложены друг на друга, и понять причину невозможно.
- **Один контейнер** на всю генерацию: удалить и перегенерировать становится одной строкой.

## Генерация на сервере

Всегда сервер: клиентская генерация даст каждому игроку свою карту, и это выглядит как полтергейст.

Что обязательно после генерации:

- **Проверка якорей.** Все части сгенерированного мира `Anchored = true`. Прогони проверку из `building-models.md`: одна забытая деталь провалится под карту.
- **Проверка проходимости.** Если генератор может создать тупик, проверь путь (raycast или `PathfindingService`) и перегенерируй, а не отдавай игроку сломанную карту.
- **Уборка предыдущей карты.** Забытые старые куски накапливаются между раундами и топят сервер.

## Ограничивай случайность

Чистый рандом даёт плохой результат: три одинаковые секции подряд, невозможные скачки, скучные участки. Правила, которые исправляют это дёшево:

- **Не повторяй последнюю секцию.** Одна строка кода, огромная разница в ощущении.
- **Веса вместо равной вероятности.** Редкие секции реже, базовые чаще.
- **Гарантированные элементы.** Раз в N секций обязательно награда или чекпоинт. Без гарантии ребёнок может не встретить награду вовсе.
- **Ограничивай сложность по позиции.** Первые секции только простые, независимо от рандома. Сложное начало отпугивает.

Это и есть разница между "случайно" и "процедурно". Случайность без правил ощущается как хаос, а не как разнообразие.

## Производительность генерации

- Генерируй порциями с `task.wait()` между ними: генерация тысячи объектов в одном кадре даёт фриз и может выкинуть игроков.
- Свойства до `Parent`, `Parent` последним: иначе каждый объект реплицируется недоделанным.
- Объединяй мелкую декорацию: тысяча отдельных частей рисуется дороже, чем одна модель.
- Для больших карт включай `StreamingEnabled` и учитывай последствия для клиентского кода, см. `physics-and-raycast.md`.

## Шум для рельефа

`math.noise` даёт плавный шум Перлина для холмов и распределения объектов.

```lua
local function heightAt(x: number, z: number, seed: number): number
	local SCALE = 0.02      -- меньше = более плавный рельеф
	local AMPLITUDE = 30
	return math.noise(x * SCALE, z * SCALE, seed) * AMPLITUDE
end
```

Складывай несколько частот (мелкая деталь поверх крупной формы) для естественности. Но помни: для мультяшной детской игры плавный реалистичный рельеф часто хуже, чем явные читаемые платформы. Читаемость важнее естественности.
