# Готовые экраны: загрузка, настройки, инвентарь, магазин, туториал

Стиль и верстка — в `ui-style.md` и `ui-implementation.md`. Здесь конкретные экраны и то, что в них ломается.

## HUD

Постоянно видимое: валюта, здоровье, прогресс уровня, активный квест. Больше ничего.

- Валюта в верхнем правом углу, крупно, с иконкой. Пульсирует при изменении.
- Здоровье над персонажем или снизу по центру, крупной цветной полоской.
- Не занимай нижние углы: там мобильный джойстик и кнопка прыжка.
- Всё, что не нужно каждую секунду, убирай в кнопки-иконки по краю экрана.

Обновляй HUD по событию от сервера, а не в цикле. И никогда не показывай "0" как факт, пока данные не загрузились: покажи заглушку или анимацию загрузки, иначе ребёнок решит, что прогресс потерян.

## Loading screen

Живёт в `ReplicatedFirst`, потому что должен появиться раньше всего остального.

```lua
local ReplicatedFirst = game:GetService("ReplicatedFirst")
ReplicatedFirst:RemoveDefaultLoadingScreen()

-- Свой экран в PlayerGui, потом ждём готовности игры
local gui = script.Parent.LoadingGui:Clone()
gui.Parent = player:WaitForChild("PlayerGui")

if not game:IsLoaded() then
	game.Loaded:Wait()
end
-- Плюс предзагрузка критичных ассетов
ContentProvider:PreloadAsync(criticalAssets)
fadeOutAndDestroy(gui)
```

Обязательно: прогресс или хотя бы анимация. Статичная картинка без движения читается как зависание. И держи таймаут: если что-то не загрузилось, всё равно пусти игрока внутрь через несколько секунд, а не держи навсегда.

Предзагружай только критичное (иконки UI, звуки кнопок). Предзагрузка всего затягивает вход, а дети не ждут.

## Settings menu

Минимум опций, крупные переключатели: музыка, звуки, качество графики, чувствительность (если есть кастомная камера).

Ключевое: **сохраняй настройки в данных игрока**, а не только в памяти клиента. Настройка, которую надо выставлять каждый вход, хуже отсутствия настройки.

Переключатели делай визуальными (тумблер, который явно слева или справа, с цветом), а не чекбоксами: дети читают состояние по форме и цвету быстрее, чем по галочке.

Громкость применяй через `SoundGroup`, чтобы одна настройка меняла все звуки категории сразу.

## Inventory UI

`ScrollingFrame` с `UIGridLayout`. Обязательно `AutomaticCanvasSize = Y` и `CanvasSize = UDim2.new()`, иначе половина предметов окажется недоступной — самый частый баг инвентарей.

Ячейка: крупная иконка, рамка цветом по редкости, количество в углу, обводка по стилю. Пустые ячейки показывай явно (полупрозрачный квадрат), чтобы было видно, сколько места осталось.

Взаимодействие: тап открывает карточку предмета с описанием и кнопками (надеть, продать). Двойные действия по одному тапу в детской игре опасны: ребёнок случайно продаст любимый предмет. Подтверждение на всё необратимое.

Список строй из данных, а не хардкодом. Одна функция `renderItem(itemId, count)`, вызываемая в цикле, плюс переиспользование ячеек при обновлении вместо полной перестройки: пересоздание сорока ячеек на каждое изменение даёт заметный рывок.

## Shop UI

Структура: категории сверху, сетка товаров, карточка товара с ценой и кнопкой покупки.

Обязательно:

- Цена всегда рядом с кнопкой, с иконкой валюты. Ребёнок должен видеть стоимость, не нажимая.
- Текущий баланс на виду в том же экране. Иначе непонятно, хватает ли.
- Кнопка "купить" зелёная всегда одинаково, во всех экранах игры (см. `ui-style.md`).
- Недоступный товар выглядит недоступным: приглушённый, с ценой красным. Но кнопка остаётся нажимаемой и объясняет, чего не хватает: молчаливая мёртвая кнопка читается как баг.
- Подтверждение перед покупкой за Robux обязательно, и кнопка Robux-покупки не должна стоять рядом с кнопкой обычной покупки. Случайное нажатие ребёнком — худший сценарий для отзывов.
- После покупки: заметная анимация получения предмета, обновлённый баланс, звук. Без подтверждения ребёнок не поймёт, купилось ли.

Поток покупки и серверные проверки — в `economy-and-progression.md`.

## Tutorial и onboarding

Правила для детской аудитории:

- **Учи действием, а не текстом.** "Нажми на монетку" с подсвеченной монеткой работает, абзац объяснения нет.
- Один шаг за раз. Подсветка через `Highlight` плюс стрелка или пульсирующий круг на цели.
- Первая награда в первые 30 секунд, до конца обучения.
- Возможность пропустить обязательна: часть детей уже играла раньше.
- Сохраняй факт прохождения в данных игрока, иначе туториал будет повторяться каждый вход.
- Не блокируй управление полностью. Дай ребёнку двигаться, пока идёт подсказка: полная блокировка ощущается как зависание.

Прогресс обучения держи как явное состояние на сервере (номер шага), а не как набор флагов на клиенте. Иначе выход в середине обучения сломает его на следующем входе.

## Модальные окна и подтверждения

Фоновый фрейм на весь экран с `Active = true` и полупрозрачностью, панель сверху по `ZIndex`. Без перехватывающего фона ребёнок нажмёт кнопку под затемнением.

Подтверждение: два крупных кнопки, зелёная слева (да), красная справа (нет), обе с иконками. Никогда не делай кнопку отказа мелкой или спрятанной: это тёмный паттерн, и в детской игре он неприемлем.

Закрытие по кнопке-крестику в углу плюс по фоновому клику для необязательных окон. Для подтверждений фоновый клик отключай, иначе случайный тап отменит выбор.

## Общая архитектура UI

Один контроллер на экран (`ShopController`, `InventoryController`), общие компоненты в модулях (`CartoonButton`, `ItemCard`), тема в одном месте. Логика в контроллере, данные приходят от сервера событием.

Никогда не держи игровое состояние в UI. Состояние живёт в данных, UI его отображает. Инвентарь, читающий количество предметов из подписи на ячейке, рассинхронизируется в первый же час.
