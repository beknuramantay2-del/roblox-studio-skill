# Звук, музыка, свет, атмосфера, VFX

Это то, что превращает работающую игру в живую. В детских играх звук и эффекты важнее графической точности: ребёнок оценивает игру по ощущению, а не по реализму.

## Звуковые эффекты

Где размещать звук решает, кто его услышит:

- `Sound` внутри `BasePart` — трёхмерный, слышен рядом с объектом. Настраивай `RollOffMaxDistance`.
- `Sound` в `SoundService` или в `PlayerGui` — плоский, слышен всегда одинаково. Для UI и музыки.
- Звук, созданный на клиенте, слышит только он. На сервере — все. Для звуков UI это важно: серверный клик услышит вся карта.

```lua
-- Клиентский звук интерфейса: один экземпляр, переиспользуем
local click = Instance.new("Sound")
click.SoundId = "rbxassetid://ID"
click.Volume = 0.4
click.Parent = SoundService

local function playClick()
	click:Play()  -- повторный Play перезапускает, это нормально для UI
end
```

Что обязательно в детской игре:

- **Звук на каждое нажатие, награду и отказ.** Без звука мультяшный UI ощущается мёртвым.
- Громкость 0.3-0.5: дети играют со звуком и часто без наушников, громкие звуки пугают.
- Не создавай новый `Sound` на каждое воспроизведение частого эффекта: это течёт памятью. Переиспользуй или ставь `Debris:AddItem`.
- Группы громкости (`SoundGroup`) для музыки и эффектов отдельно, чтобы настройки в меню работали (см. `ui-screens.md`).
- `PlaybackSpeed` со случайным разбросом 0.95-1.05 на часто повторяющихся звуках: без этого одинаковый звук за минуту начинает раздражать.

## Музыка

Музыкальная система на клиенте: список треков, плавный переход между ними, реакция на состояние игры (лобби, бой, победа).

```lua
local function crossfade(from: Sound?, to: Sound, duration: number)
	to.Volume = 0
	to:Play()
	TweenService:Create(to, TweenInfo.new(duration), { Volume = TARGET_VOLUME }):Play()
	if from then
		local fade = TweenService:Create(from, TweenInfo.new(duration), { Volume = 0 })
		fade.Completed:Connect(function()
			from:Stop()  -- останавливаем только после затухания
		end)
		fade:Play()
	end
end
```

Резкое переключение музыки слышно и выглядит как баг. Кроссфейд 1-2 секунды решает.

Дай возможность выключить музыку в настройках и **запомни выбор** в данных игрока. Ребёнок, который выключил музыку, не хочет делать это каждый вход.

## Lighting и Atmosphere

Мультяшный стиль требует света, а не драмы. Тёмные сцены детей пугают и мешают ориентироваться.

Базовые настройки под яркий стиль:

- `Technology = ShadowMap` (`Future` красивее, но дороже для телефонов).
- `Brightness` 2-3, `OutdoorAmbient` тёплый и не слишком тёмный: он определяет цвет теней.
- `Ambient` не чёрный: чистый чёрный в тенях убивает мультяшность.
- `Atmosphere` с небольшой `Density` и тёплым `Color` даёт мягкую глубину. `Haze` в пределах 1-2, больше — и всё утонет в тумане.
- `Bloom` слабый и мягкий: он даёт ту самую "игрушечную" подсветку. Сильный превращает экран в кашу.
- `DepthOfField` в детской игре обычно вреден: смазывает то, на что ребёнок смотрит.
- `Sky` с яркими облаками, `Clouds` в `Terrain` для объёма.

Локальные источники (`PointLight`, `SpotLight`) ставь экономно: они дорогие. Больше нескольких десятков активных источников на карте — просадка на телефоне. Для свечения объекта дешевле `Neon` материал, чем настоящий свет.

## Day/Night cycle

```lua
-- Только на сервере: иначе у игроков будет разное время суток.
local MINUTES_PER_REAL_SECOND = 2

RunService.Heartbeat:Connect(function(dt)
	Lighting.ClockTime = (Lighting.ClockTime + dt * MINUTES_PER_REAL_SECOND / 60) % 24
end)
```

Практика: `Lighting.ClockTime` реплицируется, поэтому меняй его на сервере. Ночь делай не слишком тёмной, иначе дети перестанут видеть, куда идти. Если ночь по геймплею страшная, дай источник света в руки.

Меняй вместе с временем не только `ClockTime`, но и `Ambient` с `Atmosphere`: тогда переход выглядит осмысленно, а не просто "выключили лампочку".

## Weather

Погода — это набор состояний, переключаемых сервером, и визуал, собираемый клиентом. Сервер решает "сейчас дождь", клиент рисует частицы и меняет освещение.

Почему так: частицы дождя на сервере — это тысячи реплицируемых объектов и гарантированный лаг. Клиент отрисует то же самое бесплатно.

Держи погоду простой: ясно, дождь, туман. Каждое состояние меняет `Atmosphere`, добавляет один `ParticleEmitter` у камеры и звук. Больше вариантов не даст пропорционального впечатления.

## VFX и ParticleEmitter

Эффекты в мультяшном стиле: яркие, крупные, короткие. Долгие тонкие эффекты не читаются на маленьком экране.

```lua
local emitter = Instance.new("ParticleEmitter")
emitter.Texture = "rbxassetid://ID"
emitter.Rate = 0                       -- не льём постоянно
emitter.Lifetime = NumberRange.new(0.3, 0.6)
emitter.Speed = NumberRange.new(8, 14)
emitter.SpreadAngle = Vector2.new(180, 180)
emitter.Color = ColorSequence.new(Theme.Color.Gold)
emitter.Size = NumberSequence.new({
	NumberSequenceKeypoint.new(0, 0.6),
	NumberSequenceKeypoint.new(1, 0),   -- сжимается к концу
})
emitter.Parent = effectPart

emitter:Emit(20)                       -- разовый выброс
Debris:AddItem(effectPart, 2)          -- обязательная уборка
```

Правила:

- **`Emit(n)` для разовых событий**, `Rate` только для постоянных (факелы, дым). Постоянный эмиттер, забытый включённым, тихо жрёт производительность.
- **Каждый эффект получает `Debris:AddItem`.** Эффекты — главный источник мусора в `Workspace`.
- **Создавай эффекты на клиенте**, когда это возможно: сервер шлёт "было попадание в точке X", клиенты рисуют. Серверные частицы реплицируются и стоят дорого.
- Не более 20-40 частиц на эффект. Больше не заметно, а на телефоне заметно по FPS.
- `Beam` и `Trail` требуют двух `Attachment` (см. `engine-basics.md`). Для следов от оружия и лучей это дешевле частиц.
- `Highlight` — самый дешёвый способ подсветить объект (цель, интерактив, врага). В детской игре он же лучший способ показать "вот сюда нажми".

Обратная связь важнее красоты: попадание должно давать вспышку, звук и число урона **в тот же кадр**, до подтверждения сервера. Ощущение отзывчивости строится именно на этом.
