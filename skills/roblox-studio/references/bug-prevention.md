# Как не наделать багов

Это главный файл скилла. Ошибки ниже дают 90% багов в детских Roblox-играх, и почти все они не падают сразу, а всплывают через 20 минут игры или только на телефоне. Проходи по разделам, когда пишешь новое, и когда чинишь непонятное.

## 1. Утечки соединений

Каждый `Connect` держит ссылку. Пока соединение живо, объект не удаляется из памяти, даже если ты сделал `Destroy`. Через час игры это тысячи мёртвых подписок, и игра начинает тормозить непонятно почему.

Правило: у каждого `Connect` должен быть очевидный ответ на вопрос "кто это отключит". Если ответа нет — используй Trove из `snippets/Trove.lua`.

```lua
local trove = Trove.new()
trove:Connect(humanoid.Died, onDied)
trove:Add(billboardGui)

player.CharacterRemoving:Connect(function()
	trove:Clean()  -- одной строкой снимаем всё
end)
```

Особенно следи за подписками **внутри** других подписок: `PlayerAdded → CharacterAdded → Touched` без уборки создаёт новую подписку на каждый респавн, и на пятой смерти игрока событие срабатывает пять раз.

Подписки на `RunService.Heartbeat` и `RenderStepped` внутри функций, которые вызываются много раз, — та же ловушка, только дороже: они жрут кадр.

## 2. Гонки загрузки

Порядок появления объектов в Roblox не гарантирован. Клиент может стартовать раньше, чем реплицировался `ReplicatedStorage`, а `Character` появляется позже игрока.

```lua
-- плохо: nil на быстром старте
local remote = ReplicatedStorage.Remotes.RequestPurchase

-- хорошо: с таймаутом, чтобы не висеть вечно
local remotes = ReplicatedStorage:WaitForChild("Remotes", 10)
if not remotes then
	warn("[Shop] Remotes не появились, магазин отключён")
	return
end
```

Всегда указывай таймаут в `WaitForChild`. Без него ошибка выглядит как "скрипт молча не работает" — худший вид бага, потому что в Output пусто.

Персонаж: не полагайся на то, что он уже есть.

```lua
local character = player.Character or player.CharacterAdded:Wait()
local humanoid = character:WaitForChild("Humanoid", 5)
```

И помни: при респавне это **новый** персонаж. Все ссылки на старый Humanoid, части тела и анимации становятся мусором. Пересобирай их в `CharacterAdded`.

## 3. Nil там, где ты его не ждал

Игрок может выйти в любой момент, включая середину твоего `task.wait`.

```lua
task.wait(3)
if not player.Parent then return end  -- вышел, дальше нельзя
```

Перед работой с игроком после любой задержки проверяй, что он ещё в игре. Иначе получишь ошибки в DataStore и в UI, которые видны только в логах живого сервера.

При включённом StreamingEnabled части `Workspace` физически отсутствуют у клиента. Клиентский код не должен считать, что дальняя модель есть: `FindFirstChild` вернёт `nil` совершенно законно.

## 4. Двойные срабатывания

Самый частый детский баг: одна монетка даёт награду три раза, потому что `Touched` стреляет на каждую часть тела.

```lua
local claimed = false
part.Touched:Connect(function(hit)
	if claimed then return end
	local player = Players:GetPlayerFromCharacter(hit.Parent)
	if not player then return end
	claimed = true
	giveReward(player)
	part:Destroy()
end)
```

Флаг ставь **до** награды, не после. Между началом функции и начислением может пройти кадр, и второе касание успеет проскочить.

То же на кнопках UI: быстрый двойной тап отправляет два remote. Ставь локальный кулдаун на клиенте (для отзывчивости) **и** на сервере (для честности) — клиентский кулдаун ничего не защищает, он только про приятность.

## 5. Ожидание, которое никогда не кончится

`RemoteFunction:InvokeClient` — не используй никогда. Клиент может не ответить, и серверный поток повиснет навсегда. Если серверу нужны данные от клиента, шли `RemoteEvent` в обе стороны с таймаутом на ожидание.

Аналогично `WaitForChild` без таймаута, `:Wait()` на событии, которое может не случиться, и `repeat task.wait() until condition` без счётчика попыток. Любое ожидание должно иметь выход.

## 6. Ошибки, которые никто не увидел

В отдельном потоке (`task.spawn`, коллбек события) необработанная ошибка убивает только этот поток. Остальная игра работает, а фича молча не срабатывает.

Поэтому в критичных обработчиках событий проверяй входные данные явно и логируй отказы через `warn` с префиксом системы. "Ничего не произошло" отлаживать нечем.

## 7. Физика и якоря

Неотъякоренная декоративная деталь падает через пол при первом касании. Всё, что не должно двигаться, — `Anchored = true`. Забытый якорь на одной части из ста находится только плейтестом, поэтому проверяй сразу после генерации моделей (см. `building-models.md`).

Массовое создание неотъякоренных частей ещё и топит сервер физикой.

## 8. Порядок инициализации

Если UI читает баланс до загрузки данных, ребёнок увидит 0 монет и решит, что прогресс потерян. Клиент должен либо ждать первого пакета данных, показывая заглушку, либо получать данные push-ом от сервера сразу после загрузки. Никогда не рисуй "0" как факт, пока данных нет.

## Как чинить, когда уже сломалось

1. Прочитай реальную ошибку в Output со стеком. Не гадай.
2. Воспроизведи. Баг, который ты не можешь вызвать по желанию, ты не починишь, а замаскируешь.
3. Сузь: сервер или клиент? Одно место или все? Первый раз или после респавна? Ответы обычно указывают прямо на раздел выше.
4. Меняй одно за раз. Три правки одновременно и "вроде заработало" означают, что ты не знаешь, что было причиной, и баг вернётся.
5. Починил — добавь `print`-проверку или защитное условие, чтобы тот же класс ошибок в следующий раз проявился громко.
