# Сборка моделей и окружения

Визуальный язык мира должен совпадать с UI: яркий, мультяшный, читаемый. Тот же принцип, что и в интерфейсе — крупные простые формы, насыщенный цвет, никакого реализма.

## Стиль мира

- **Крупные простые формы.** Ребёнок должен понимать объект по силуэту. Мелкая детализация на телефоне превращается в кашу и стоит производительности.
- **Скругления через `Part` с `CornerWedge`, `MeshPart` со сглаженными формами или `SpecialMesh`.** Прямоугольные кирпичи выглядят как незаконченный прототип.
- **Материалы:** `SmoothPlastic` и `Plastic` — база стиля. `Neon` для важного (валюта, порталы, кнопки), `ForceField` для эффектов. Реалистичные `Concrete`, `Slate`, `Rock` ломают мультяшность, используй их только осознанно.
- **Цвет насыщенный, но с целью.** Интерактивное ярче фона. Если вся сцена одинаково яркая, ребёнок не найдёт, куда идти.
- **Освещение:** `Lighting.Technology = ShadowMap`, тёплый `OutdoorAmbient`, лёгкий `Bloom`. Мультяшность требует света, а не драмы: тёмные сцены в детских играх пугают и мешают ориентироваться.

## Гигиена структуры

```
Workspace/
├── Map/          статика окружения
├── Interactive/  всё, с чем игрок взаимодействует
└── Effects/      временные объекты, создаваемые в рантайме
```

Модель обязана иметь `PrimaryPart`. Без него `PivotTo`, `MoveTo` и клонирование ведут себя непредсказуемо: объект телепортируется не туда или разлетается.

Осмысленные имена (`CoinPickup`, а не `Part73`). Через MCP ты находишь объекты именно по имени, и мусорные имена делают навигацию невозможной.

## Якоря — главный источник поломок

**Всё, что не должно двигаться, `Anchored = true`.** Одна забытая деталь падает через карту при первом касании, и найти её потом можно только глазами.

После любой генерации частей прогоняй проверку:

```lua
for _, descendant in workspace.Map:GetDescendants() do
	if descendant:IsA("BasePart") and not descendant.Anchored then
		warn("[Build] не отъякорено:", descendant:GetFullName())
	end
end
```

Для декора также ставь `CanCollide = false` и `CanTouch = false`: игрок не должен застревать в кустах, а лишние коллизии стоят физики.

## Теги и атрибуты вместо поиска по имени

Поиск по имени (`if part.Name == "Coin"`) ломается при переименовании и не масштабируется. `CollectionService` решает это правильно.

```lua
local CollectionService = game:GetService("CollectionService")

for _, coin in CollectionService:GetTagged("Coin") do
	setupCoin(coin)
end

-- монеты, добавленные позже, тоже подхватятся
CollectionService:GetInstanceAddedSignal("Coin"):Connect(setupCoin)
```

Параметры конкретного объекта храни в атрибутах, а не в скрытых `IntValue`:

```lua
coin:SetAttribute("Value", 5)
local value = coin:GetAttribute("Value") or 1  -- дефолт на случай отсутствия
```

Атрибуты видны в Studio, редактируются дизайнером без кода и реплицируются автоматически. Дефолт через `or` обязателен: атрибут может быть не выставлен, и без дефолта получишь nil в арифметике.

## Объекты в рантайме

Свойства задавай до `Parent`. Назначение родителя первым запускает репликацию и пересчёт физики на недоделанном объекте.

```lua
local part = Instance.new("Part")
part.Size = Vector3.new(2, 2, 2)
part.Anchored = true
part.Material = Enum.Material.SmoothPlastic
part.Parent = workspace.Effects  -- последним
```

Всё созданное в рантайме должно иметь план на удаление: `Debris:AddItem(effect, 3)` или Trove. Иначе `Workspace` за час игры распухает до тысяч мёртвых объектов, и сервер начинает тормозить.

## Клонирование

Шаблоны держи в `ReplicatedStorage` (если нужны клиенту) или `ServerStorage` (только сервер). Не храни шаблоны в `Workspace` с `Visible = false` — они всё равно грузятся и реплицируются всем.

При клонировании проверяй, что `PrimaryPart` на месте, и ставь позицию через `PivotTo`, а не через `Position` отдельных частей: иначе модель разъедется.

## Что нельзя делать за пользователя

Массовое удаление или перестройка существующего `Workspace` — только с его согласия. Ручную работу человека в Studio восстановить нечем, в отличие от твоего кода. Если нужно заменить объект, переименуй старый в `Name_old` и оставь.
