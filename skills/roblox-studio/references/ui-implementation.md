# Верстка UI: чтобы не развалилось на телефоне

Большинство игроков — телефон в руках, экран 5 дюймов, иногда с вырезом. UI, собранный на глаз в окне Studio, там гарантированно поедет. Ниже минимум, который это предотвращает.

## Scale, а не Offset

`UDim2` состоит из Scale (доля от родителя, 0-1) и Offset (пиксели). Правило простое:

- **Scale** для всего, что должно расти вместе с экраном: панели, окна, ряды, отступы.
- **Offset** только для того, что обязано остаться фиксированным: толщина рамки, иконка ровно в 24 пикселя.

```lua
-- плохо: на телефоне вылезет за экран
frame.Size = UDim2.new(0, 800, 0, 600)

-- хорошо: половина экрана на любом устройстве
frame.Size = UDim2.fromScale(0.5, 0.6)
frame.Position = UDim2.fromScale(0.5, 0.5)
frame.AnchorPoint = Vector2.new(0.5, 0.5)
```

`AnchorPoint` в центре вместе с позицией в Scale — самый надёжный способ отцентрировать окно. Без AnchorPoint элемент цепляется левым верхним углом и на другом соотношении сторон уезжает.

## Пропорции держит UIAspectRatioConstraint

Чистый Scale растягивает элемент вместе с экраном: на широком мониторе круглая иконка станет овальной, а панель — вытянутой полосой.

```lua
local ratio = Instance.new("UIAspectRatioConstraint")
ratio.AspectRatio = 1.5  -- ширина к высоте
ratio.DominantAxis = Enum.DominantAxis.Height
ratio.Parent = panel
```

Ставь на все панели и квадратные иконки. `DominantAxis.Height` обычно правильнее: высота экрана меняется меньше, чем ширина.

## Границы размера

```lua
local size = Instance.new("UISizeConstraint")
size.MinSize = Vector2.new(220, 120)
size.MaxSize = Vector2.new(900, 600)
size.Parent = panel
```

`MinSize` спасает от нечитаемого UI на маленьком экране, `MaxSize` — от абсурдно раздутой панели на 4K-мониторе.

## Компоновку делают Layout-объекты, не ручные координаты

Ручная расстановка десяти кнопок означает десять правок при добавлении одиннадцатой. Layout расставляет сам.

- `UIListLayout` — вертикальные и горизонтальные списки. Ставь `SortOrder = Enum.SortOrder.LayoutOrder`, иначе порядок будет алфавитным по имени и поедет при переименовании.
- `UIGridLayout` — инвентарь и сетка предметов.
- `UIPadding` — внутренние отступы. Задавай в Scale (`UDim.new(0.05, 0)`), чтобы они масштабировались вместе с панелью.
- Внутри Layout свойство `Position` игнорируется. Не пытайся его выставлять, это частая путаница.

```lua
local list = Instance.new("UIListLayout")
list.FillDirection = Enum.FillDirection.Vertical
list.SortOrder = Enum.SortOrder.LayoutOrder
list.Padding = UDim.new(0.03, 0)
list.HorizontalAlignment = Enum.HorizontalAlignment.Center
list.Parent = container
```

Для прокручиваемых списков: `ScrollingFrame` плюс `AutomaticCanvasSize = Enum.AutomaticSize.Y` и `CanvasSize = UDim2.new()`. Тогда область прокрутки считается сама и не будет классического бага, когда половина предметов недоступна.

## Общий масштаб через UIScale

Чтобы весь UI подстроился под маленький экран, не трогая каждый элемент, вешай `UIScale` на корневой фрейм и пересчитывай при изменении окна:

```lua
local camera = workspace.CurrentCamera
local BASE_HEIGHT = 720

local function updateScale()
	local height = camera.ViewportSize.Y
	uiScale.Scale = math.clamp(height / BASE_HEIGHT, 0.7, 1.4)
end

updateScale()
trove:Connect(camera:GetPropertyChangedSignal("ViewportSize"), updateScale)
```

`clamp` обязателен: без него UI на планшете раздувается, а на узком экране схлопывается в нечитаемое.

## Safe area: вырезы и системные жесты

Верхняя левая зона — кнопка меню Roblox, нижняя — жесты системы. Ничего интерактивного туда не ставь.

- Отступ сверху не меньше 10% высоты для элементов у верхнего края.
- `IgnoreGuiInset = false` (по умолчанию) на `ScreenGui`, чтобы Roblox сам сдвинул контент ниже системной панели. Ставь `true` только осознанно, для фоновых слоёв.
- Кнопки джойстика на мобилке занимают нижние углы. HUD у нижнего края будет перекрыт, держи важное в центральной полосе.

## Ввод: не только мышь

- Используй `Activated` на `TextButton`/`ImageButton`, а не `MouseButton1Click`: второй не сработает на геймпаде.
- `Selectable = true` и `NextSelectionUp/Down/Left/Right`, если целишься в консоли.
- Hover-эффекты (`MouseEnter`) на телефоне не существуют. Всё важное должно быть видно без наведения, на hover только украшения.
- Проверяй `UserInputService.TouchEnabled`, чтобы показать нужную подсказку: "Нажми" вместо "Кликни".

## Порядок слоёв

`ZIndex` внутри одного `ScreenGui`, `DisplayOrder` между разными. Держи структуру предсказуемой: HUD ниже, панели выше, попапы и подтверждения на самом верху. Модальное окно должно перехватывать ввод фоновым фреймом на весь экран с `Active = true` и `BackgroundTransparency` около 0.5, иначе ребёнок нажмёт кнопку под затемнением.

## Частые причины "кнопка не нажимается"

Почти всегда одно из четырёх: сверху лежит прозрачный фрейм с `Active = true`; у родителя `Visible = false`; `ZIndex` ниже перекрывающего элемента; соединение навешено до появления объекта, потому что забыт `WaitForChild`. Проверяй перекрытие первым, догадки тут тратят время.

## Собирай UI кодом, а не мышью

Через MCP UI надёжнее генерировать скриптом: код повторяем, версионируется и правится за секунду. Пиши генератор идемпотентно (см. `mcp-workflow.md`), чтобы повторный запуск не плодил копии. Фабрики компонентов держи в одном модуле, иначе стиль разойдётся между экранами.
