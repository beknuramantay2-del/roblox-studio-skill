# Тактика для средних моделей

Эта инструкция компенсирует слабую рабочую память и склонность к преждевременной генерации.

## Working memory card

Перед каждым шагом держи максимум:

```text
Goal:
Mode:
Current system:
Last verified change:
Files/paths changed:
Open error:
Next action:
Proof required:
```

После каждого инструмента обновляй только изменившиеся строки. Не пересказывай весь проект.

## Anti-drift

- Не меняй название объекта без поиска references.
- Не добавляй новый service, если существующий уже отвечает за эту ответственность.
- Не генерируй код до того, как назван parent и сторона выполнения.
- Не делай массовую операцию, пока один экземпляр не проверен.
- Не исправляй симптом в UI, пока не проверен server state и Output.
- Не продолжай после ошибки с новым предположением: сначала зафиксируй stack trace.

## Micro-steps

Разбивай задачу на шаги, каждый с одним наблюдаемым результатом:

1. нашёл путь;
2. прочитал код;
3. создал/изменил один объект;
4. проверил свойства;
5. запустил узкий тест;
6. только потом расширил.

## Stop conditions

Остановись и спроси пользователя, если найдено разрушительное расхождение: несколько конкурирующих сервисов, неизвестный владелец DataStore, конфликт Script Sync/Rojo, риск удаления, production purchase, непроверенный внешний asset или невозможность доказать результат. Не угадывай.
