# Vector3, CFrame, UDim2, Color3 и математика движка

Ошибки в этих типах обычно не падают, а дают неправильное поведение: модель смотрит не туда, UI съезжает, объект улетает в бесконечность. Поэтому важнее не синтаксис, а понимание, что именно ты считаешь.

## Vector3: точка и направление

```lua
local position = Vector3.new(10, 5, -3)
local up = Vector3.yAxis                    -- (0, 1, 0), читаемее чем new(0,1,0)
local delta = target.Position - part.Position
local distance = delta.Magnitude            -- длина
local direction = delta.Unit                -- то же направление, длина 1
```

Ключевые вещи:

- **`Magnitude` для расстояния**, а не покомпонентное сравнение. `(a - b).Magnitude <= radius` — правильная проверка близости.
- **`Unit` на нулевом векторе даёт NaN.** Проверяй `if delta.Magnitude > 0` перед `Unit`, иначе объект улетит в бесконечность, а причину будешь искать долго: NaN проходит любые сравнения молча.
- **`Vector3` иммутабелен.** `v.X = 5` не сработает, создавай новый: `Vector3.new(5, v.Y, v.Z)`.
- Горизонтальное расстояние (игнорируя высоту) считай, обнулив Y. Важно для NPC, которые иначе "не достают" до игрока на возвышении.
- `:Dot()` показывает, смотрит ли объект на цель: `lookVector:Dot(direction) > 0.7` примерно означает "в пределах 45 градусов спереди". Дешёвая замена тригонометрии.
- `:Lerp(other, alpha)` для плавного смешивания позиций.

Запомни оси: Y — высота, X и Z — плоскость. `Vector3.new(0, 50, 0)` это вверх. Путаница осей — причина половины багов со спавном и полётом.

## CFrame: позиция плюс поворот

`CFrame` описывает и где объект, и куда он смотрит. Двигать объект надо им, а не отдельно `Position` и `Orientation`.

```lua
-- позиция плюс взгляд на цель
part.CFrame = CFrame.lookAt(spawnPosition, targetPosition)

-- поворот в градусах
part.CFrame = CFrame.new(position) * CFrame.Angles(0, math.rad(90), 0)

-- сдвиг в локальных координатах объекта: на 5 единиц вперёд от себя
local ahead = part.CFrame * CFrame.new(0, 0, -5)

-- полезные части
local look = part.CFrame.LookVector    -- куда смотрит
local right = part.CFrame.RightVector
local pos = part.CFrame.Position
```

Что надо помнить:

- **Умножение не коммутативно.** `a * b` и `b * a` дают разные результаты. `cframe * offset` означает сдвиг в локальных осях объекта, `offset * cframe` — в мировых. Путаница здесь даёт оружие, которое стреляет в сторону.
- **Вперёд это минус Z.** Поэтому сдвиг вперёд записывается как `CFrame.new(0, 0, -distance)`.
- **Углы в радианах.** `math.rad(90)`, а не `90`. Забытый `math.rad` даёт поворот на пять с лишним тысяч градусов, то есть визуально случайный.
- `CFrame.lookAt(from, to)` — самый простой способ развернуть объект на цель, вместо ручной тригонометрии.
- Для моделей: `model:PivotTo(cframe)` и `model:GetPivot()`. Прямая запись `Position` отдельным частям модель разорвёт.
- Плавный поворот: `current:Lerp(target, alpha)` в цикле.

## UDim2 и UDim: размеры UI

`UDim` это пара `{Scale, Offset}`: доля от родителя плюс пиксели. `UDim2` — то же по двум осям.

```lua
UDim2.fromScale(0.5, 0.3)      -- половина ширины, треть высоты родителя
UDim2.fromOffset(200, 50)      -- строго 200 на 50 пикселей
UDim2.new(0.5, -10, 0, 40)     -- смешанно: половина минус 10px, ровно 40px
```

Практика: Scale для всего, что должно масштабироваться, Offset только для фиксированного. Подробно с констрейнтами и адаптивностью — в `ui-implementation.md`.

`UDim.new(0.25, 0)` в `UICorner.CornerRadius` даёт радиус, растущий вместе с элементом. Это правильный способ держать круглые формы на любом экране.

## Color3 и цвет

```lua
Color3.fromRGB(255, 200, 60)     -- как в дизайне, 0-255
Color3.new(1, 0.78, 0.23)        -- 0-1, для расчётов
Color3.fromHSV(0.12, 0.8, 1)     -- удобно для оттенков и плавных радуг
```

- Дизайнерские значения бери через `fromRGB`: перевод в 0-1 руками — источник опечаток.
- Затемнение и осветление делай через хелперы в `snippets/Theme.lua`, а не умножением на глаз: единый способ держит палитру целостной.
- Для плавных переходов цвета — `Color3:Lerp(other, alpha)`.
- `ColorSequence` нужен для `UIGradient`, `ParticleEmitter`, `Beam`, `Trail`.

## NumberSequence и NumberRange

Нужны для эффектов: прозрачность и размер частиц во времени (`NumberSequence`), разброс значений (`NumberRange`).

```lua
emitter.Transparency = NumberSequence.new({
	NumberSequenceKeypoint.new(0, 1),    -- появился прозрачным
	NumberSequenceKeypoint.new(0.2, 0),  -- проявился
	NumberSequenceKeypoint.new(1, 1),    -- растворился
})
emitter.Lifetime = NumberRange.new(0.4, 0.8)
```

Ключевые точки обязаны начинаться с 0 и заканчиваться на 1, иначе движок бросит ошибку.

## Случайность

Используй `Random.new()` вместо `math.random`, когда важна воспроизводимость: объект `Random` принимает seed и даёт одинаковую последовательность. Для генерации карт это критично, иначе один и тот же сид даст разные миры.

```lua
local rng = Random.new(seed)
local value = rng:NextNumber(0, 1)
local roll = rng:NextInteger(1, 100)
local point = rng:NextUnitVector()
```

Для наград и лута заводи отдельный `Random` на систему: так шанс дропа не будет коррелировать со случайностями в других местах игры.
