# Безопасность: не доверяй клиенту

Любой игрок может запустить произвольный код на своём клиенте. Значит: всё, что приходит от клиента, — это запрос, а не факт. В детских играх это не абстракция, читы для популярных механик лежат в открытом доступе, и первый же читер сломает экономику для всех.

## Что где считается

На сервере: валюта, инвентарь, здоровье, урон, прогресс, проверка расстояния, кулдауны, награды, сохранение.

На клиенте: ввод, камера, звук, анимация UI, предсказание для отзывчивости.

Если сомневаешься — сервер. Клиентская валюта означает бесконечную валюту.

## Валидация каждого remote

Обработчик на сервере не имеет права предполагать, что аргументы правильные. Клиент может прислать что угодно: `nil`, таблицу вместо числа, `math.huge`, `NaN`, строку в миллион символов.

```lua
Remotes.RequestPurchase.OnServerEvent:Connect(function(player, itemId)
	-- 1. тип
	if type(itemId) ~= "string" then return end
	-- 2. длина, чтобы не приняли мегабайт текста
	if #itemId > 40 then return end
	-- 3. существование в белом списке
	local item = Config.ShopItems[itemId]
	if not item then return end
	-- 4. кулдаун
	if not RemoteGuard.check(player, "Purchase", 0.5) then return end
	-- 5. право совершить действие
	if CoinService.GetBalance(player) < item.Price then
		Remotes.PurchaseFailed:FireClient(player, "not_enough")
		return
	end
	ShopService.Purchase(player, itemId)
end)
```

Порядок неслучаен: сначала дешёвые проверки типов, потом кулдаун, и только потом обращения к данным. Иначе спам remote-ами заставит сервер тысячу раз читать баланс.

Числа проверяй полностью: `type(n) == "number" and n == n and n ~= math.huge and n >= min and n <= max`. Проверка `n == n` отсекает NaN — он проходит любые сравнения и портит данные так, что потом непонятно, что случилось.

Первый аргумент `OnServerEvent` — это `player`, который Roblox подставляет сам, подделать его нельзя. Никогда не принимай игрока как аргумент от клиента: это классическая дыра, позволяющая действовать от чужого имени.

## Кулдауны обязательны

Без ограничения частоты remote можно спамить тысячи раз в секунду и уронить сервер. Обёртка в `snippets/RemoteGuard.lua`. Кулдаун на клиенте — только для приятности, защиты в нём ноль.

## InvokeClient не использовать

Сервер повиснет навсегда, если клиент не ответит, и это делается одной строчкой на стороне читера. Нужны данные от клиента — `RemoteEvent` в обе стороны с таймаутом.

## Проверка расстояния и правдоподобности

Клиент говорит "я собрал монетку" — сервер проверяет, что игрок физически рядом:

```lua
local MAX_REACH = 20
local root = player.Character and player.Character.PrimaryPart
if not root then return end
if (root.Position - coin.Position).Magnitude > MAX_REACH then return end
```

То же для скорости передвижения, частоты выстрелов, скорости прогресса. Аномалию логируй, но не кикай сразу: лаги и телепорты дают ложные срабатывания, а несправедливо выкинутый ребёнок больше не вернётся.

## Сохранение данных

`DataStore` может упасть, и это нормальный сценарий, а не исключение. Все обращения через `pcall`, с повторами и задержкой между ними. Готовая обёртка в `snippets/DataStoreService.lua`.

Критично:

- Сохранять при выходе игрока **и** периодически (каждые 2-3 минуты). Краш сервера без периодического сохранения = потерянный прогресс = плачущий ребёнок.
- `BindToClose` для сохранения при остановке сервера.
- Никогда не перезаписывать данные значением, полученным с ошибкой. Загрузка упала — работай на дефолтах в памяти и **не сохраняй**, иначе затрёшь реальный прогресс нулями. Это самый дорогой баг в жанре.
- Валидируй загруженное: структура могла измениться между версиями игры. Недостающие поля добавляй дефолтами.

## Что не защитит

Обфускация клиентского кода, `LocalScript`-античит, скрытые `ReplicatedStorage`-значения. Всё это читается и обходится. Единственная реальная защита — сервер, который считает сам и никому не верит.
